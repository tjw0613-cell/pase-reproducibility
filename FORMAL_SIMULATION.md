# Figures 3 and 4: current status and requirements

The unified negative-binomial design is a separate planned study. At this repository's preparation, the protocol archive has not been publicly registered and no formal outputs are available. The executable entry points deliberately stop with exit code 2. `all-ready` excludes them, and no successful figure manifest or image is written for them.

Before implementing their plotting adapters, retain all of the following:

1. The actual publicly accessible, version-specific protocol archive and its SHA-256, with its public date preceding formal draws if prospective specification is claimed. A locally generated timestamp does not establish public registration.
2. The locked design and actual condition membership, eligible populations, separate equal-mean/Fisher targets, seeds, controls, planned precision rules and explicit stopping schedule.
3. The completed official run, including run identity, exact reference tables and uncertainties, every attempted/available denominator, per-shard checksums and completion checks. Missing or failed fits must remain in the attempt counts.
4. Final summaries of conditional coverage, rejection rates, interval availability, joint availability-and-coverage, widths, bias and RMSE, with Monte Carlo uncertainty and the correct target scale.
5. A verified mapping from those outputs to the planned main-matrix and interaction panels. A latent mean-zero generating input is not automatically an observed-score null. Precision and zero-null controls require the corresponding recorded checks.

The registered design includes a 100-condition exploratory screen, which must remain identified separately. Public registration must reflect the actual order of events; an analysis already examined cannot be made prospective by renaming it. The completed Gaussian benchmarks and small count-native pilot remain available in Figures 2 and 5 and do not supply missing evidence for Figures 3 and 4.

This repository does not bundle or launch the formal simulator. When verified results are available, update the status, implement and test the plotting adapters, and release the new package with a new identifier. Do not relabel `not_available` as `ready` without those results.
